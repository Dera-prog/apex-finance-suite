Fourteen fixes, ranked by trust

Ordered by how much each one protects a user's confidence in their money. Each card states the problem, the pattern, and the acceptance test that closes it. Several are already in the shipped client; the rest are scoped for the next pass.

Priority key. P0 — a user could be misled about money. P1 — friction that costs completion. P2 — polish with measurable payoff.

P0 · Never lie about money

These five close the gap between what the screen says and what the ledger knows.

01 · One submitting model for every write

P0

Six different money actions used to manage their own busy flags, some with double-submit windows. One shared state machine removes the class of bug.

BeforeTap twice → two deposits
AfterLocked on first press, spinner + label
AcceptanceAll seven write endpoints share a submit guard; a rapid double-tap in any flow produces exactly one ledger entry; the button exposes aria-busy.

02 · Offline means refused, not failed

P0

A dead server behind a proxy returns HTML, which used to read as a generic rejection. It must say the server was unreachable and confirm nothing moved.

Before"That did not go through."
Shipped"Could not reach the Apex server. Check your connection and try again."
Acceptance502/503/504 and non-JSON responses classify as offline; balance unchanged; the entered amount survives; a banner appears above the action.

03 · The server's sentence is the error

P0

Client-side copies drift from the real rules. Show the ledger's own refusal where the action lives, in the user's language.

Before"Something went wrong."
After"Amount is more than your available wallet balance."
AcceptanceEvery 400 body with a message renders under its field or on its sheet verbatim; the draft is preserved; no balance changes.

04 · Receipts with a copyable reference

P0

"Success" is not proof. A receipt names the new balance, the counterparty and a reference support can trace.

BeforeToast disappears in 2 s
AfterReceipt screen + reference + new balance
AcceptanceEvery successful write ends on a receipt with server reference; copy action confirms for 2 s; the same entry appears in Activity within one navigation.

05 · Session expiry never eats the draft

P0

Sessions last 30 days, but when they end mid-flow the user should re-authenticate in place, not restart the transfer.

Before401 → generic error
Shipped"Sign in again" panel inside the open sheet → verify → retry with the same draft
AcceptanceA 401 opens the OTP sheet over the current screen; after verification the original action retries with the same payload; no duplicate entry.

P1 · Remove the friction

Completion and clarity fixes, mostly copy, layout and input behaviour.

06 · Plan locks announced before commitment

P1

Fixed plans are a promise, not a surprise. The lock and maturity date belong on the configure sheet, before the first naira moves.

BeforeDiscover the lock on detail
AfterRule + date on configure, then progress on detail
AcceptanceOpening a fixed plan shows the maturity date and lock rule before confirm; the disabled withdrawal explains why in one sentence.

07 · Amount entry that respects limits

P1

Presets, a Max that equals the real available amount, and decimal handling that never produces kobo the ledger rejects.

BeforeFree text, silent truncation
AfterPresets + Max + live "Available ₦68,400.00"
AcceptanceMax fills the exact server-owned balance; inputs accept kobo; values under ₦100 or over the tier limit explain themselves inline.

08 · Empty states with one clear next step

P1

A zero balance is the most common new-user state; it should teach, not look broken.

BeforeBlank activity list
AfterIllustration + "Add money" + what will appear
AcceptanceWallet, Activity and Plans each have a dedicated empty state with a primary action that opens the right flow.

09 · OTP ergonomics

P1

Six cells that accept a paste, walk backwards on delete, and show the resend countdown before the user asks.

BeforeRetype all six after one mistake
ShippedPaste fills, errors shake once, timer visible
AcceptancePasting a 6-digit SMS fills every cell; wrong code keeps the digits for correction; rate-limit copy includes the wait time.

10 · Sync, stated once

P1

Because balances are server-owned, a small "Updated just now · synced" line on Overview and Wallet explains why another device agrees.

BeforeUnknown freshness
Shipped"Updated just now" beside the balance
AcceptanceTimestamp updates on every successful read; stale (> 60 s) reads show "Refreshing…" and retry silently once.

11 · Sheets behave like sheets

P1

Review and receipt surfaces get focus management, Esc/backdrop dismissal, and a visible grab handle.

BeforeFocus stays behind the modal
AfterTrapped focus, Esc closes, focus returns
AcceptanceKeyboard focus is trapped while open and restored to the trigger on close; Esc and backdrop both dismiss; heading receives focus on open.

P2 · Polish with payoff

Cheap wins once the trust layer is solid.

12 · Activity that remembers

P2

Keep the chosen filter and search across visits, and restore scroll when a receipt sheet closes.

BeforeEvery visit starts on "All" with an empty search
ShippedFilter, query and scroll return where you left them
AcceptanceReturning to Activity restores the last filter and query; closing a detail sheet returns to the same scroll offset.

13 · Biometric unlock on mobile

P2

The mobile app already ships a passkey module; surface it as an opt-in unlock for returning sessions.

AcceptanceUsers can enable Face/Touch unlock after OTP; failure falls back to the OTP sheet without losing the session.

14 · Follow the system theme

P2

Add a "System" option beside Light and Dark, applied before first paint on both apps.

BeforeLight flash on every load before the saved theme applies
ShippedSystem honoured before first paint; manual choice persists
AcceptanceSystem preference is honoured on first load with no light flash; manual choice still wins and persists.

Two short iterations, each ending in something demonstrable on the live build.

Measure

Task success

Instrument deposit, transfer and plan-open completion per session; watch the drop-off after the first refusal.

Measure

Time to proof

Median seconds from app open to a receipt, split by returning and new users.

Measure

Support traces

Count messages containing a reference or "did it go through" — the P0 set should reduce these.
